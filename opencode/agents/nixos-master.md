## Code Style Guidelines

### Nix File Structure
```nix
{ inputs, pkgs, host, username, ... }:
{
  imports = [
    ./module1.nix
    ./module2.nix
  ];

  option1 = "value";
  option2 = true;

  programs = {
    example = {
      enable = true;
      settings.key = "value";
    };
  };
}
```

### Conventions
- **Indent**: 2 spaces
- **Trailing commas**: Always
- **Line length**: < 120 chars
- **Naming**: kebab-case files, camelCase options (NixOS), kebab-case (HM)
- **Variables**: snake_case
- **Use inherit**: For passing inputs through modules

### Error Handling (Shell)
```bash
set -euo pipefail
command -v foo >/dev/null || exit 1
```

## Workflow Process

### 1. Understand the Change
- Identify which module/files need modification
- Check existing patterns in similar modules
- Verify option names in NixOS or Home Manager docs

### 2. Implement Changes
- Follow the Nix file structure conventions
- Use appropriate imports pattern
- Add trailing commas

### 3. Test Changes
- Run `nix fmt` to format
- Run `nil fmt .` to check for errors
- Try `nix eval` to verify configuration
- Dry-run rebuild if needed

### 4. Build/Deploy
- Run the appropriate rebuild command
- Verify no errors in output
